# NEXORA RPG architecture

Status: initial RPG domain foundation implemented; multiplayer gameplay integration is still in progress.

## Product direction

NEXORA is a standalone fantasy MMORPG with its own Android client and its own versioned client/server protocol. Minecraft/Bedrock is not a required client platform. Do not add a dependency on Bukkit, Nukkit, or a Minecraft server API to the game domain.

## Server-authoritative layers

1. **Runtime foundation** — lifecycle, tick loop, diagnostics and configuration.
2. **World simulation** — dimensions, chunks, biomes, block state, world generation and persistence.
3. **Content registries** — stable namespaced IDs for classes, items, abilities, entities, effects, recipes and quests.
4. **RPG domain** — character profile, class selection, attributes, level progression, skills, cooldowns, combat calculations and status effects.
5. **Gameplay systems** — quests, NPC interactions, dungeons, boss encounters, loot tables, guilds and economy.
6. **Network/session** — authenticated player sessions, versioned messages and authoritative state replication.
7. **Android client** — renderer, touch/controller input, HUD, inventory, character sheet, skill bar and UI themes.

The server owns all authoritative values: XP, level, attributes, health, mana, cooldowns, inventory, equipment, combat outcomes, loot and currency. The client may predict presentation but cannot award rewards or decide combat results.

## Initial RPG domain slice

The first domain slice defines:
- Immutable base attributes: vitality, strength, agility, intelligence and defense.
- Namespaced class definitions and a deterministic class registry.
- Four initial archetypes: Warrior, Mage, Ranger and Guardian.
- Server-side XP progression up to level 100.
- Five unspent attribute points per level.
- A pure progression service with bounded validation and deterministic unit tests.

These are initial balancing placeholders, not final class balance. The data model is independent of the Android UI and can later be loaded from validated content packs.

## Planned progression and combat

- Character creation assigns one class; class changes are an explicit server-side operation with policy/cost.
- Attribute allocation is validated server-side and recorded in player persistence.
- Skills are data-driven definitions with unlock level, resource cost, cooldown, target rules and effect list.
- Combat is resolved on the server using validated range, line-of-sight, cooldown, resource, equipment and status checks.
- Loot and quest rewards are generated by server-owned tables and persisted atomically with player progress.
- All persistent identifiers are namespaced; saved data carries schema versions and migration rules.

## Implementation order

1. Class registry and XP progression (implemented).
2. Persistent player RPG profile and attribute allocation.
3. Authenticated player session binding and server-authoritative movement.
4. Health, mana, equipment and combat event pipeline.
5. Skill definitions, cooldowns and ability execution.
6. NPCs, quests, loot tables, dungeons and bosses.
7. Client HUD, character sheet, skill bar and inventory integration.
8. Multiplayer load, persistence recovery and exploit-focused tests.

## Compatibility and security

- The NEXORA client connects only through the NEXORA protocol unless a separately verified adapter is added.
- No untrusted client message may directly mutate XP, attributes, inventory, currency or entity health.
- Development network mode remains restricted to trusted private networks until authentication and transport deployment are complete.
- Only original or appropriately licensed assets may ship with the game.
